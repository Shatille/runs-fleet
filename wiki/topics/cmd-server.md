# Server (Orchestrator Entry Point)

## Purpose [coverage: medium -- 2 sources]
The `cmd/server` binary is the long-running orchestrator daemon. It receives GitHub webhooks at `/webhook`, enqueues jobs onto SQS, starts EC2 fleets, reconciles warm pools, handles spot interruption events, consumes agent termination telemetry, runs housekeeping tasks, and exposes the admin API plus the GitHub Actions cache protocol. The backend is EC2-only — there is no runtime branch on a Kubernetes provider. Multiple replicas may run concurrently; coordination uses per-pool and per-task DynamoDB locks rather than global leader election.

## Architecture [coverage: medium -- 3 sources]
Boot sequence in `main()` ([cmd/server/main.go](../../cmd/server/main.go)). Every step below either succeeds or `os.Exit(1)` — the file has no nil-degrade paths for anything load-bearing (see Key Decisions):

1. `logging.Init()`; root context from `signal.NotifyContext(ctx, os.Interrupt, syscall.SIGTERM)`.
2. `config.Load()` reads and validates env vars ([config-bootstrap](config-bootstrap.md)); `gh.ParseAliasRules(cfg.LabelAliasesJSON)` builds the label-alias resolver and logs the rule count.
3. `tracing.Setup(ctx, cfg.Tracing)` installs the OpenTelemetry tracer provider (noop when tracing is disabled) via `otel.SetTracerProvider`.
4. AWS config. `awsobs.Middlewares()` returns the observability middleware plus an `awsObsRecorder`; `awsobs.PerOperationTimeout(config.AWSPerOpTimeout, map[string]bool{"ReceiveMessage": true})` builds the per-operation timeout with SQS long-poll exempted. `awsconfig.LoadDefaultConfig` composes region, a custom HTTP client (`newAWSHTTPClient(config.AWSResponseHeaderTimeout)`), `awsRetryer`, and `WithAPIOptions(append(awsObsMiddlewares, perOpTimeout))` — observability registered **first** so it stays outermost and times a timeout abort. A second config, `sqsCfg`, clones `awsCfg` with `newAWSHTTPClient(config.AWSSQSResponseHeaderTimeout)` so a 20s long poll does not trip the 10s response-header timeout.
5. Core deps: `initJobQueue(sqsCfg, cfg)` (SQS), `db.NewClient(awsCfg, poolsTable, jobsTable)` plus optional `SetJobsPoolStatusGSI` / `SetJobsInstanceIDGSI` / `SetAuditTable`, `cache.NewServer`.
6. `initMetrics(awsCfg, cfg)` builds the publisher and (if enabled) the Prometheus handler; `awsObsRecorder.SetPublisher(metricsPublisher)` then installs it into the middleware, which emitted to a no-op until this point. The ordering is forced: the CloudWatch backend is built *from* `awsCfg`, which already carries the middleware.
7. EC2 path, built unconditionally: `fleet.NewManager`, `pools.NewManager`, `events.NewHandler(eventsQueueClient, dbClient, metricsPublisher, cfg)` + `SetJobQueue(jobQueue)`, an `ec2.NewFromConfig` client wired into the pool manager. Each manager gets `SetMetrics(metricsPublisher)`.
8. `initCircuitBreaker` (only when `cfg.CircuitBreakerTable` is set and the fleet manager exists) builds `circuit.NewBreaker`, starts its cache cleanup, and wires it into both the fleet manager and the event handler.
9. `initSecretsStore` builds the SSM or Vault backend; `poolManager.SetRunnerConfigChecker` wraps it as a `pools.RunnerConfigChecker`. When `cfg.TerminationQueueURL` is set, `termination.NewHandler(...)` is built over its own queue client.
10. `initGitHubClient(cfg)` builds a single `*gh.Client` (nil when App credentials are absent). When non-nil it is fanned out to three consumers: `terminationHandler.SetGitHubJobChecker` (the still-queued re-dispatch check), `eventHandler.SetGitHub(&eventsRerunAdapter{...})` (spot-reclaim job re-run, PR #454), and `initHousekeeping`.
11. `initHousekeeping` returns both the scheduled `housekeeping.Runner` and its `housekeeping.Tasks` executor (nil,nil when `dbClient` or `cfg.PoolsTableName` is missing) so the admin API can drive the same sweeps on demand. It wires `SetPoolDB`, `SetJobRequeuer(jobQueue)`, `SetFleetCostStore(dbClient)` (the fleet-cost sampler), and — when the GitHub client exists — `SetGitHubJobChecker` and `SetRunnerRegistry`. When `cfg.CostReportSNSTopic` or `cfg.CostReportBucket` is set it builds `cost.NewReporter(awsCfg, dbClient, spot, cfg, ...)`, guarding the typed-nil `*fleet.Manager` before it lands in the `cost.SpotPricer` interface. The runner gets `SetMetrics` and `SetTaskLocker(dbClient, uuid.NewString())`.
12. `fleet.NewAMIResolver(ec2Client, cfg.LaunchTemplateName)` — deliberately **one** resolver shared by the admin console and the staleness sweep, so the two cannot disagree about which AMI is current for a whole cache TTL. Handed to `housekeepingTasks.SetAMIReference`.
13. `initRunnerManager(githubClient, secretsStore, cfg)` builds `runner.Manager` (nil if no GitHub client), carrying `CacheSecret`, `BaseURL`, `TerminationQueueURL`, `BuildkitCacheBucket`/`Region`, and `RunnerLogsBucket` (the last three all riding `cfg.CacheBucketName`).
14. `worker.DirectProcessor` plus a 10-slot `directProcessorSem` for the webhook fast path.
15. The `webhookServer` struct is assembled and `setupHTTPRoutes(ctx, cacheServer, prometheusHandler)` registers everything on an `http.ServeMux`; a route-setup error (e.g. OIDC discovery failure) exits.
16. `http.Server` on `:8080` (15s read/write, 60s idle).
17. Workers launched onto a shared `sync.WaitGroup` via a `runWorker` closure: `worker.RunEC2Worker`, `poolManager.ReconcileLoop`, `eventHandler.Run`, plus `terminationHandler.Run` and `housekeepingRunner.Run` when non-nil. The HTTP listener runs in its own goroutine, outside the WaitGroup.
18. Block on `<-ctx.Done()`, then shut down in this order: `ws.beginDrain(cfg.ShutdownDrainDelay)` (flip `/ready` to 503 and keep serving for the drain delay so the load balancer deregisters first) → `server.Shutdown(shutdownCtx)` → `waitForWorkers(&workers, workerDrainTimeout)` → `tracing.Shutdown` → `metricsPublisher.Close()`.

`internal/worker/common.go` provides the shared polling primitive `RunWorkerLoopWithTicker` (wrapped by `RunWorkerLoopWithObservers`/`RunWorkerLoop`): an `idlePollInterval` (25s) ticker triggers `drainQueue`, which calls `q.ReceiveMessages(ctx, maxMessagesPerReceive=10, receiveWaitSeconds=20)` and keeps re-receiving while batches come back full (so a backlog isn't throttled to one batch per tick). Each message is dispatched to a goroutine bounded by a `maxConcurrency = 5` semaphore, tracked by a `sync.WaitGroup` so shutdown waits for in-flight work. Each processor runs under `context.WithTimeout(context.WithoutCancel(ctx), config.MessageProcessTimeout)` — detached from the signal context so an already-dispatched processor finishes instead of aborting on SIGTERM — with a panic recover that reports `"error"` to the process observer.

## Talks To [coverage: medium -- 2 sources]
Internal packages imported by `main.go`: `internal/awsobs`, `internal/handler`, `internal/worker`, `pkg/admin`, `pkg/cache`, `pkg/circuit`, `pkg/config`, `pkg/cost`, `pkg/db`, `pkg/events`, `pkg/fleet`, `pkg/github` (aliased `gh`), `pkg/housekeeping`, `pkg/logging`, `pkg/metrics`, `pkg/pools`, `pkg/queue`, `pkg/runner`, `pkg/secrets`, `pkg/termination`, `pkg/tracing`. There is no import of a `pkg/provider` package — the Kubernetes provider abstraction was removed upstream (see Key Decisions).

AWS SDK clients constructed directly in this file: `ec2.NewFromConfig` (one in `main` for the pool manager, one in `setupHTTPRoutes` for admin handlers), `dynamodb.NewFromConfig`, `sqs.NewFromConfig` (admin queue handler), and `s3.NewFromConfig` + `s3.NewPresignClient` (the jobs handler's runner-log source, only when `cfg.CacheBucketName` is set). All of them derive from `awsCfg`/`sqsCfg` and therefore carry the `internal/awsobs` middleware.

Adapters declared at the bottom of `main.go`, each existing to narrow one shared client to one consumer's interface: `poolDBAdapter` (`*db.Client` → `housekeeping.PoolDBAPI`), `eventsRerunAdapter` (→ `events.JobRerunner`), `terminationJobCheckerAdapter` (→ `termination.GitHubJobStatusChecker`, preserving the raw status string), `adminJobCheckerAdapter` (→ `admin.GitHubJobStatusChecker`, also carrying `RunnerName`), `githubJobCheckerAdapter` (→ `housekeeping.GitHubJobChecker`, adding a `Completed` bool), `runnerRegistryAdapter` (→ `housekeeping.RunnerRegistry`), and `runnerConfigCheckerAdapter` (`secrets.Store` → `pools.RunnerConfigChecker`, mapping `ErrConfigNotFound` to `false, nil`).

External: GitHub API via `github.com/google/go-github/v57/github` (event types) and `pkg/github.Client` for App-auth installation tokens; Vault optionally via the secrets backend; an OIDC issuer at startup when admin auth is configured.

## API Surface [coverage: high -- 2 sources]
HTTP routes registered in `webhookServer.setupHTTPRoutes` on port `:8080`:

- `GET /health` — always 200 OK.
- `GET /ready` — 503 while `shuttingDown` is set; otherwise calls `queue.Pinger.Ping` on the job queue with a 2s timeout and 503s on failure (`handleReadiness`).
- `GET <cfg.MetricsPrometheusPath>` — Prometheus scrape endpoint, registered only when the Prometheus backend is enabled (`prometheusHandler != nil`).
- Cache protocol routes via `cache.NewHandlerWithAuth(...).RegisterRoutes(mux)` (HMAC-authenticated with `cfg.CacheSecret`).
- Admin handlers on a nested `adminMux`, mounted at `/api/` behind `admin.NewRateLimiter(cfg.AdminRateLimit).Wrap(...)` and gated by `admin.NewAuthMiddleware(cfg.AdminSessionSecret)` (native OIDC session cookies): `admin.NewAuthHandler` (`/api/auth/{login,callback,logout,config}`), `admin.NewHandler` (also takes `cfg.HotPoolCaps` so the console validates overrides against the same ceilings the tuner clamps to), `admin.NewJobsHandler` (`SetAuditDB`, plus `SetLogSource` over S3 when a cache bucket exists), `admin.NewHungHandler`, `admin.NewInstancesHandler` (`SetAMIResolver`), `admin.NewQueuesHandler` (all six queue URLs), `admin.NewCircuitHandler`, `admin.NewHousekeepingHandler`, `admin.NewRequeueHandler`, `admin.NewCostHandler` (`SetFleetCostStore` + `SetReportLocation(cfg.ReportLocation())`, which **must** match the zone the fleet sampler writes day keys in), and `admin.NewMetricsHandler` (taking the cost handler as its month-to-date provider so both pages report one figure).
- `GET /admin/` — admin web UI via `admin.UIHandler()`.
- `POST /webhook` — `handleWebhook`: rejects non-POST with 405, validates HMAC via `gh.ParseWebhook(r, cfg.GitHubWebhookSecret)` (400 on failure), then `processWebhookEvent` performs the durable work synchronously, writes 200, and hands the best-effort remainder to `runPostAck` (a panic-recovered goroutine on `context.Background()`, because the request context dies when the handler returns):
  - `action=queued` → `handler.HandleWorkflowJobQueued` enqueues a `queue.JobMessage`. The postAck closure publishes enqueue metrics, calls **`ws.poolNotifier.NotifyPoolDemand(jobMsg.Pool)`** when the pool name is non-empty, ≤63 chars, and matches `validPoolName` (`^[a-zA-Z0-9][a-zA-Z0-9_-]*$`), and then runs `worker.TryDirectProcessing` under the 10-slot semaphore.
  - `action=in_progress` → `handler.HandleWorkflowJobInProgress` (pure filter, no I/O) derives a `StartupObservation` from GitHub's own `created_at`/`started_at`, only when the runner name carries the `runs-fleet-` prefix AND the labels parse; postAck calls `handler.PublishJobStartupMetrics`. `ws.dbClient` is typed-nil-guarded before assignment to `handler.JobStartupDB`.
  - `action=completed` with `conclusion=cancelled` → the entire cleanup (`handler.HandleJobCancelled`) runs post-ack, because it costs a read, a conditional write and an EC2 call, and GitHub redelivers webhooks it waits too long for; the conditional flip makes a redelivered copy a no-op.
  - `action=completed` with `conclusion=failure` → `handler.HandleJobFailure` may re-queue synchronously (capped at `maxJobRetries = 2`, runner-name-prefix gated, `ForceOnDemand: true`); postAck publishes requeue and queue-depth metrics.
  - any other action/conclusion → 200 with `Event acknowledged`, no work.

## Data [coverage: low -- 0 sources]
Not applicable. The server owns no persistent state directly. All state lives in the DynamoDB tables managed by `pkg/db` (`runs-fleet-jobs`, `runs-fleet-pools`, `runs-fleet-circuit-state`, optional audit table), S3 (`runs-fleet-cache`), and the SQS queues. See [state-storage](state-storage.md).

## Key Decisions [coverage: medium -- 4 sources]
- **2026-08: `initMetrics` returns a `NoopPublisher` when nothing is enabled — and that is now the default shape.** The function appends a publisher per enabled backend (CloudWatch, Prometheus, Datadog), returns `metrics.NoopPublisher{}` if the slice is empty, the single publisher if there is exactly one, and `metrics.NewMultiPublisher(...)` otherwise. Since PR #456 flipped `RUNS_FLEET_METRICS_CLOUDWATCH_ENABLED` to default `false`, CloudWatch — previously the only backend on by default — no longer makes the difference between noop and real, so a deployment that sets no metrics env var now publishes nothing at all. Nothing else in the boot path changed: every `Publish*` call site and the backend itself are untouched, and re-enabling is one env var. A Datadog constructor failure is a warning, not a fatal: it drops that backend and keeps the others.
- **`NotifyPoolDemand` is called from the webhook postAck path, not the durable path.** A `queued` webhook for a `pool=` job pokes the pool manager so reconciliation runs immediately instead of waiting out the 60s tick — but only after GitHub has been acked, and only for a pool name that passes the `validPoolName` regex and the 63-char cap. This is also the highest-frequency reconcile trigger in the system, which is why it featured in the CloudWatch cost analysis behind #456.
- **Publisher installation is deliberately two-phase.** `awsobs.Middlewares()` must be registered while building `awsCfg`, but the CloudWatch publisher is built *from* `awsCfg`. The recorder therefore holds its publisher behind an atomic pointer and emits to a no-op until `SetPublisher` lands — so the first few AWS calls of a boot are genuinely unmeasured, by design rather than by bug.
- **Fail loudly rather than nil-degrade.** `config.Load`, `ParseAliasRules`, `tracing.Setup`, `awsconfig.LoadDefaultConfig`, `gh.NewClient` (when credentials *are* present), `secrets.NewStore`, and `setupHTTPRoutes` all `os.Exit(1)` on error. The reasoning is economic: a degraded orchestrator keeps accepting webhooks and burning EC2 spend on jobs it cannot complete, which is worse than a crash-looping pod.
- **Shutdown drains before it stops listening.** `beginDrain` flips `/ready` to 503 and *keeps serving* for `cfg.ShutdownDrainDelay` so the load balancer deregisters the task first; webhooks routed during the deregistration window still enqueue (they run on the request context, not the cancelled signal context) instead of hitting a closed listener and 502-ing, which would strand the job with no runner. The delay runs before the shutdown clock starts and is bounded by `config.MaxShutdownDrainDelay`.
- **OIDC discovery is bounded at startup.** `oidcDiscoveryTimeout = 15s` covers the case where the issuer is black-holed and never responds — a fast HTTP error already fails startup via the returned error, but an unresponsive connection would otherwise hang `main()` forever instead of failing loudly.
- **One AMI resolver, two consumers.** Sharing `fleet.NewAMIResolver` between the instances console and the staleness sweep prevents the two from caching independently and disagreeing about the current AMI for a full TTL — which would let the page call an instance stale that the sweep considers fine, or the reverse.
- **Typed-nil guards at every interface boundary.** A nil `*fleet.Manager`, `*db.Client`, `*gh.Client`, or `*housekeeping.Tasks` assigned directly to an interface produces a *non-nil* interface, defeating the callee's nil check. `main.go` guards each one explicitly before assignment (`cost.SpotPricer`, `handler.JobStartupDB`, `admin.GitHubJobStatusChecker`, `admin.OrphanInstanceSweeper`, `cost.FleetCostStore`).
- **2026-08: the pool audit housekeeping task was deleted.** `ExecutePoolAudit` only republished `PoolInstances`/`PoolDesired` under the same names and dimensions that pool reconciliation already writes, making it a second, staler writer into one time series (and paying for a non-paginated pools-table `Scan` every 10 minutes to do it).
- **2026-07: shared GitHub client.** `initGitHubClient(cfg)` builds one `*gh.Client` and fans it out through adapters, so a token cached for an owner by one consumer is reused by the others instead of each maintaining its own installation-token cache.
- **2026-06: Kubernetes backend removed.** `pkg/provider` no longer exists; `main.go` does not branch on a backend mode and unconditionally builds the EC2 path.
- Single binary, multiple goroutines, one `runWorker` closure onto one `sync.WaitGroup`, so shutdown waits for all of them uniformly.
- Multi-instance deployment without leader election: pool reconciliation and housekeeping both take DynamoDB locks (`SetTaskLocker(dbClient, uuid.NewString())` — one random owner id per replica).
- Fast-path direct processing: `worker.TryDirectProcessing` opportunistically processes the job inline behind a 10-slot semaphore, bypassing the SQS round trip; the always-enqueued SQS copy is the fallback.
- Graceful shutdown ordering: drain → HTTP stop → worker drain (bounded by `workerDrainTimeout = MessageProcessTimeout + 10s`) → tracing flush → metrics close, so in-flight jobs' final spans and metrics are captured.

## Gotchas [coverage: medium -- 3 sources]
- **A deployment with no metrics env vars now emits nothing.** Before #456, CloudWatch's default-on meant `initMetrics` almost never returned the `NoopPublisher`. It is now the default outcome, and it is silent: the "metrics initialized" log line is only emitted when at least one backend exists, so the absence of metrics looks like the absence of a log line.
- Worker drain timeout (`workerDrainTimeout = MessageProcessTimeout + 10s`) plus `ShutdownDrainDelay` plus the telemetry flush must all fit inside the deploy's `terminationGracePeriodSeconds` / `stopTimeout`, or the platform SIGKILLs mid-drain.
- Receive errors from a cancelled/deadline-exceeded context are logged at `Warn`, not `Error`, to avoid noisy shutdown logs; other receive errors are `Error` (`internal/worker/common.go`).
- Direct-processing semaphore is sized to 10; bursts beyond that fall through to normal queue processing (no error, just a skipped fast path).
- The webhook handler responds 200 for every event it recognises *and* every event it ignores; only HMAC/parse failures produce 400 and non-POST produces 405. A silently-unhandled action is indistinguishable from a handled one at the HTTP layer.
- `NotifyPoolDemand` silently skips a pool whose name fails `validPoolName` or exceeds 63 chars — the job is still enqueued, it just waits for the next 60s reconcile tick.
- `HandleJobFailure` requires the runner name to begin with `runs-fleet-`; failures for other runner names are silently skipped. Max retries is enforced inside `internal/handler`, not here.
- Circuit breaker is only wired when `cfg.CircuitBreakerTable` is set and the fleet manager exists (`initCircuitBreaker` early-returns otherwise).
- Termination and housekeeping are gated on config: termination requires `cfg.TerminationQueueURL`; housekeeping requires `cfg.PoolsTableName` (it needs the table for task locking). Missing config silently disables them (nil handler, never started).
- Without GitHub App credentials, `initGitHubClient` returns nil after a **warning, not an error** — and that silently disables four separate features: the runner manager (so no runner ever registers), housekeeping's stale-job and orphaned-runner sweeps, the admin hung-jobs checker, the termination still-queued re-dispatch, and the spot-reclaim job re-run. This is the one nil-degrade path the file keeps.
- SQS `ReceiveMessage` calls use a dedicated `sqsCfg` (longer response-header timeout) precisely because its 20s long-poll wait would otherwise exceed both `AWSResponseHeaderTimeout` and `AWSPerOpTimeout` on the default `awsCfg`; other SQS operations (`SendMessage`, `DeleteMessage`) are fast enough to stay on the bounded path.
- `costAdminHandler.SetReportLocation(ws.cfg.ReportLocation())` and the fleet-cost sampler's day keys must use the same zone or the two disagree about which day a cost belongs to — the reason `RUNS_FLEET_REPORT_TIMEZONE` is a hard startup error rather than a UTC fallback ([config-bootstrap](config-bootstrap.md)).
